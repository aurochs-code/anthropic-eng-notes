# 分镜：context-window（长时任务中的上下文窗口：填满、清理、压缩、笔记、子智能体）

## 基本信息

- **所属笔记**：`notes/effective-context-engineering-for-ai-agents.md`
- **插入位置**：`## 图解` 里，`### 图 3：长时任务的三种技术如何选` 的图解文字之后，新增 `### 图 4：长时任务中上下文窗口的变化`。备选位置：`### 4. 长时任务的三种技术` 表格之后。由大厨按版面决定。
- **组件类型**：token 窗口时间轴（试点后计划复用到 Agent Skills、用代码执行调用 MCP、4 月 23 日复盘三篇）。
- **一句话机制**：上下文窗口容量有限，内容越多模型越难准确找回信息；长任务里要么就地腾空间（清理旧工具结果、压缩成摘要），要么把信息放到窗口外（结构化笔记、子智能体的独立窗口），只把精炼的部分带回来。
- **形式**：分步（8 步），不自动播放。

## 分步说明（8 步）

1. **开局**：每次调用模型，系统提示和工具定义都要占一块窗口，这部分一直在。
2. **工作几轮之后**：用户消息、模型回复和工具调用的原始结果不断追加，工具结果往往占得最多。
3. **接近上限**：窗口快满了。原文提醒，不只是“放不下”的问题，窗口里的 token 越多，模型准确找回其中信息的能力越差（上下文腐化，context rot），所以上下文要当成有限的注意力预算来花。
4. **最轻量的做法：清理旧工具结果**。很深的历史里已经用过的原始工具结果，模型通常不需要再看一遍，换成占位即可。原文称这是最安全、最轻量的压缩形式。
5. **压缩（compaction）**：再次接近上限时，让模型总结历史，用摘要开一个新窗口。原文以 Claude Code 为例：保留架构决策、未解决的 bug 和实现细节，丢掉冗余的工具输出或消息，再带上最近访问的五个文件继续工作。压得太狠会丢掉当时看不出重要性的细节。
6. **结构化笔记（agentic memory）**：智能体定期把进度、待办写到窗口外的文件（如 NOTES.md），上下文重置后再读回来，几乎不占常驻空间。
7. **子智能体**：把需要大量探索的子任务交给各自拥有干净窗口的子智能体，它们可能各用掉数万 token，但只把约 1,000–2,000 token 的精炼摘要交回主智能体。主窗口只保留高层计划和这些摘要。
8. **怎么选**：需要大量来回对话、保持连贯的任务用压缩；有清晰里程碑的迭代开发用结构化笔记；能从并行探索中获益的复杂研究和分析用子智能体。

| 压缩：接近窗口上限时总结内容，用摘要重开一个新窗口；通常是第一个可用的手段 | “Context engineering for long-horizon tasks” → Compaction | 一致 |
