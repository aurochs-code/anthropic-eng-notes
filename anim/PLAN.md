# 动态图方案

> 状态：2026-10-18 用户已批准，先做 5 张样板（分镜见 `storyboards/`）。分工：内容侧（笔者）只写分镜和文字；框架、组件实现、代码块语法由站点工程（大厨）决定。本文是方案原文，具体语法以大厨最终定稿为准。

## 结论

1. **能配，也值得配，但只配 10 张左右，不追求每篇都有。** 现有 130 个 mermaid 图（notes 97、papers 33）讲“由哪些部分组成、按什么顺序”已经够用。mermaid 讲不清的是三类东西：**参数变化带来的结果变化**（PPO 截断、pass@k / pass^k、采样温度、GPipe 气泡）、**随时间累积的状态**（上下文窗口填满与压缩、提示缓存命中与失效）、**逐步计算**（注意力权重、LSTM 门控）。动态图只用在这三类地方。
2. **主方案：原生 TypeScript + SVG 的轻量交互组件，按需加载。** 写法和站点现在处理 mermaid 的方式一样：Markdown 里写一个 ` ```anim ` 代码块，构建时换成占位元素，同时预渲染一张静态 SVG 当兜底；浏览器里只有包含动画的页面才加载对应脚本。不引入 MDX，也不引入 React 或 Svelte。颜色用站点已有的 CSS 变量，暗色模式切换时不用重新渲染。
3. **辅助方案：mermaid 分步高亮。** 对智能体循环、RLHF、多智能体编排这类“流程走向”图，不重画，在现有 mermaid 图上逐步点亮节点即可，内容侧只需多写一个步骤列表。
4. **不推荐 GIF、视频（Manim / Motion Canvas）和 Lottie**：跟不了暗色模式，文件大，文字搜不到，改一个数字就要重新导出，也做不了参数交互。
5. **试点 5 张样板**，覆盖 4 种可复用组件加 1 个 mermaid 分步高亮。大厨的框架约 3–4 人日，样板实现约 5 人日；笔者写分镜和核对数字约 2 人日。合计约 2 周，验收后再铺开。

## 1. 候选清单（按收益排序）

## 2. 技术方案对比

**站点现状**：Astro 5 静态站，内容是纯 `.md`，没有 MDX。mermaid 由 remark 插件换成 `<pre class="mermaid">`，`Base.astro` 只在有图时动态加载，主题切换时重新渲染；mermaid 打包块约 676 KB（未压缩，按需加载）。主题全部用 CSS 变量（`--fg`、`--bg`、`--accent`、`--line` 等），通过 `html[data-theme]` 切换。已有 `prefers-reduced-motion` 的处理（目前只用在侧栏）。`check-site.mjs` 核对 mermaid 渲染、390px 无溢出、Pagefind 搜索等。

**关键约束：Astro 组件不能直接写进 `.md`。** 想用 Svelte / React 岛，要么改用 MDX（动内容管线、改扩展名、回归测试现有 remark 插件），要么仍走“占位元素 + 客户端挂载”。这条约束基本决定了选型。

| 方案 | 效果 | 暗色 / 移动端 | 体积与加载 | 维护成本 | 可访问性 | 内容侧（笔者） | 工程侧（大厨） |
|---|---|---|---|---|---|---|---|
| **A. 原生 TS + SVG 组件（主方案）** | 分步、滑块、循环都能做，清晰 | 用 CSS 变量着色，主题切换自动生效；viewBox 自适应，原生 `<input type=range>`，可按触屏设计 | 按页按需加载，每个组件估计几 KB 到十几 KB（gzip），无框架运行时 | 每张图一个 TS 模块，最好写成纯函数（参数 → SVG），好测 | 构建时预渲染的静态 SVG + 文字步骤，关 JS 也能看；减少动态效果时不自动播放；可键盘操作，aria-live 播报 | 写分镜（步骤文字、玩具数据、参数范围），核对数字 | remark 插件、加载器、通用播放器 / 滑块控件、主题色板、静态兜底、检查脚本 |
| B. 纯 CSS / SVG 关键帧动画 | 只能做简单循环和悬停，无参数 | 用 CSS 变量也能跟主题 | 最轻，无 JS | 手写 SVG 难改 | 媒体查询可关掉动画，需另加暂停 | 要自己画 SVG | 几乎不用改 |
| C. Svelte / React 岛（需 MDX） | 交互最强 | 都能做到 | React 运行时偏重；Svelte 较小 | 引入 MDX 并迁移文件，内容与工程耦合加深 | 能做到，静态兜底需额外处理 | 学 MDX 写法 | 集成 MDX，回归测试插件和检查 |
| D. D3 | 擅长数据图和曲线 | 都能做到 | 只引子模块（d3-scale、d3-shape）时可控 | 学习成本较高 | 同 A | 同 A | 在 A 的框架里按需引子模块，不单列方案 |
| E. Manim / Motion Canvas 导出视频或 GIF | 视觉最好 | 暗色要渲染两份；GIF 色彩差、文件大；移动端流量重 | 每段估计在 MB 量级，仓库膨胀 | 改一个数字就要重渲染，依赖 Python、LaTeX、ffmpeg | 要字幕和封面，文字搜不到 | 学动画工具并导出 | 托管、懒加载、封面 |
| F. Lottie | 动效细腻 | 颜色写死在 JSON 里 | 播放器本身几十 KB | 需要 AE 等设计工具，无参数交互 | 一般 | 需要会设计工具 | 引入播放器 |
| G. mermaid 分步高亮（辅助方案） | 在现有流程图上逐个点亮节点或连线 | 高亮样式由站点 CSS 提供，主题重渲染后重新挂上 | 基本不增加体积 | 低；mermaid 自动生成的节点 id 可能随版本变化，要靠检查脚本兜住 | 文字步骤列表本身就是兜底 | 在 mermaid 块旁写步骤和节点 id，不写 classDef | 写高亮挂载脚本、样式和检查 |

## 3. 推荐方案与试点

**主方案 A（原生 TS + SVG，按需引 D3 子模块）+ 辅助方案 G（mermaid 分步高亮）。** 抽出四个可复用组件，第一批基本都能拼出来：

1. **函数曲线 + 滑块**：PPO、pass@k、温度、规模定律、MDL。
2. **分步播放器 + SVG 场景**：注意力、LSTM、Bahdanau 对齐、神经图灵机寻址。
3. **token 窗口时间轴**：上下文工程、Agent Skills、代码执行调用 MCP、4 月 23 日复盘。
4. **网格 / 甘特时间轴**：GPipe、卷积滑动、空洞卷积感受野。

**内容侧写法建议（最终由大厨定）：**

- 不新增 frontmatter 字段；有没有动画由正文里有没有动画代码块决定，和现在判断 mermaid 一样。
- 正文新增代码块，示意：
  ````
  ```anim
  id: ppo-clip
  caption: 截断目标随概率比 r 的变化（示意数据）
  params: { epsilon: 0.2 }
  steps:
    - 优势为正时，r 超过 1+ε 后目标不再增长
    - 优势为负时，r 低于 1−ε 后目标不再下降
  ```
  ````
  构建时用默认参数预渲染静态 SVG，`steps` 输出成可被搜索到的文字列表；有 JS 时再增强为播放器或滑块。
- mermaid 分步高亮：mermaid 块后紧跟一个 ` ```anim-steps ` 块，列出“节点 id → 这一步的说明”。
- CONTENT-GUIDE 要补的规则：动画里的关键术语在正文里出现一次；玩具数据标“示意”；动画不替代正文解释。
- 阅读时长：建议每张动画计 0.5 分钟，和 mermaid 一致，由大厨确认。
- 检查脚本建议新增：每个占位元素挂载成功且控制台无报错；关 JS 有静态兜底；减少动态效果时不自动播放；浅色、深色都截图；390px 不溢出；页面切到后台或图滚出视口时暂停。

**工作量估算：**

| 项 | 谁 | 估算 |
|---|---|---|
| 框架：remark 插件、加载器、播放器 / 滑块控件、主题色板、静态兜底、减少动态效果、检查和截图、文档 | 大厨 | 3–4 人日 |

## 4. 风险

- **版权**：只原创，不照搬。30u30 的图和代码（CC BY-NC-ND，禁止演绎）、论文原图（如 GPipe 图 2、PPO 图 1、Transformer 结构图）、原博客的图（colah 的 LSTM 图、Karpathy 博文的图尤其容易被下意识模仿）、Anthropic 博客配图、网上流行的注意力图解，都不能复制或描摹构图。机制可以表达，构图、配色、例句、数据都自己设计，玩具数据一律自拟。图标、字体只用站点已有的或许可明确的开源资源。
- **准确性**：动画看起来很“精确”，容易让人误以为是真实数字，示意数据必须在图上标“示意”。pass^k = p^k 的前提是各次尝试相互独立，要写在图上。规模定律常数只用论文值。讲 Anthropic 内部系统的图（auto 模式、沙箱、缓存清理）只表达原文写到的逻辑，标“示意，非真实实现”。原文只有零散数据点的（如基础设施噪声），不画成连续曲线。每张图上线前由笔者对照原文逐项核对，和笔记一样保留「待核实」。
- **性能**：只在有动画的页面加载，不引入 React；滚出视口或页面切到后台时暂停；已加载 mermaid 的页面（打包块约 676 KB 未压缩）不再叠加重依赖。
- **维护**：动画是代码，需要纯函数快照单测和截图回归。mermaid 分步高亮依赖自动生成的节点 id，升级时可能失效，靠检查脚本兜住。控制在 10–15 张。
- **可访问性**：自动播放超过 5 秒必须能暂停（WCAG 2.2.2）；只靠悬停的交互在手机上要能改成点按；每张动画都要有可读的文字步骤，供读屏和搜索使用。
